### Important: Jest vs Vitest Test Utilities

**Key Difference in Test Utilities:**

**Jest:**
- Provides test utilities (`describe`, `it`, `expect`, `jest`, etc.) as **globals**
- No imports needed - they're automatically available in test files
- This is configured in Jest's test environment

**Vitest:**
- Provides test utilities as **imports** by default
- You need to explicitly import what you use in each test file
- This follows a more explicit, tree-shakeable approach

**Why the Difference:**
1. **Tree Shaking**: Vitest's approach allows bundlers to only include the test utilities you actually use, reducing bundle size
2. **Explicit Dependencies**: Makes it clear what each test file depends on
3. **Better IDE Support**: Explicit imports provide better IntelliSense and type checking
4. **Module Federation**: Works better with modern bundling strategies

**Required Imports for Vitest Test Files:**
```ts
import { describe, it, beforeEach, afterEach, vi, expect } from 'vitest';
```

- `describe`, `it`, `beforeEach`, `afterEach`, etc. (test structure)
- `expect` (assertions)
- `vi` (mocking utilities - equivalent to Jest's `jest` global)

**Example Test File Update:**
```ts
// Before (Jest - globals available)
import { formatCurrency } from './formatCurrency';

describe('formatCurrency', () => {
  it('should format currency correctly', () => {
    expect(formatCurrency(100)).toBe('£100.00');
  });
});

// After (Vitest - explicit imports)
import { describe, it, expect } from 'vitest';
import { formatCurrency } from './formatCurrency';

describe('formatCurrency', () => {
  it('should format currency correctly', () => {
    expect(formatCurrency(100)).toBe('£100.00');
  });
});
```

**Alternative: Making Vitest Globals Available**
If you prefer the Jest-style global approach, you can configure Vitest to provide globals in your `vite.config.ts`:

```ts
export default defineConfig({
  test: {
    globals: true, // This makes test utilities available globally
    // ... other config
  }
})
```

However, the **recommended approach** is to use explicit imports for better tree shaking and clarity.
