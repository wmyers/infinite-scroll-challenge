# Minimum Setup Rule

When copying or setting up a project from an example or template:

1. FIRST clearly communicate the approach:
   - "I'll start with a minimal setup focusing on core functionality"
   - "We'll begin with essential components and add more as needed"
   - "Let's implement this incrementally, starting with the basics"

2. Explain the benefits of the minimal approach:
   - Easier to understand and test core functionality
   - Faster initial setup
   - Clearer separation of concerns
   - Easier to debug issues
   - More manageable learning curve

3. Outline the planned phases:
   - Phase 1: Core functionality (what we're starting with)
   - Phase 2: Additional features (what we'll add next)
   - Phase 3: Enhancements (future improvements)

4. Get user confirmation on the approach before proceeding

Example:
User: "Copy this example project"
Assistant: "I'll start with a minimal setup focusing on the core functionality. This approach will help us:
- Understand the basic structure first
- Test core features more easily
- Add complexity incrementally

We'll begin with [core components] and then add [additional features] in the next phase. Would you like me to proceed with this approach?"

NOT:
User: "Copy this example project"
Assistant: "I'll create all the necessary files and structure based on the example."
